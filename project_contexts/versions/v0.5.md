# v0.5 — Mods + Rice sharing

> **Status:** planned · Depends on: v0.3 (themes), v0.2 (config).

## Goal
Make customization shareable, so the config-first design pays off socially.

## Scope
- **Mod format:** a folder with `.lua` files, assets and a manifest. A mod can contribute themes, **backgrounds**, keybinds, layouts, icon sets and panel geometry. Mods run in a strict sandbox: data only, no file, network or process access, no event hooks, a hard time limit.
- **Install from a registry or a git URL;** the sidebar Themes/Extensions sections gain a Mods tab.
- **Rice export:** one command packs your setup (config, theme, layouts, keybinds, extension list) into a shareable bundle.
- **Desktop integration:** read the active desktop colour scheme (e.g. from Caelestia, if present; **[VERIFY]** path and format) and offer "match wallpaper".
- **Hyprland IPC (optional):** follow compositor events such as workspace changes. **[VERIFY]** scope before committing.

## Out of scope
Monetisation, accounts, ratings, a hosted registry beyond a simple index.

## Exit criteria
- [ ] You can export your setup and a second machine reproduces it from one command.
- [ ] A mod can restyle the whole app, including sidebar geometry, with zero runtime code.
- [ ] Installing 20 mods does not measurably change idle RAM.

## Risks
- Untrusted Lua: a downloaded rice is code. The sandbox in `project_context.md` §6.3 must be tested with deliberate attacks (file reads, process spawn, endless loops, huge allocations) before sharing ships. Decide whether mods need a manifest of what they touch, shown before install.
- Registry moderation and abuse.

## Open questions
- Is a hosted registry necessary at all, or are git URLs enough for a long time?
