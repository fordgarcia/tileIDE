# v0.1 — Shell: rail, drawer, window, basic tiling

> Part of TileIDE. Feature definitions live in `../project_context.md`; visuals in `../design/design.md`.
> **Status:** planned · Depends on: v0.0 (Gate 1 passed; toolkit and Lua flavour chosen). **Fresh code:** the v0.0 spikes are deleted, not grown.

## Goal
The first version you can actually use: open a folder, edit files in tiles, run a terminal, all inside the TileIDE canvas. It must be useful on its own (T7), even with no config system and no workspaces yet.

## Scope
**Canvas and window (regions 0, 2, 3)**
- Full-screen transparent canvas with the gap ring (`gap_rail`, `gap_outer`) and the outlined, translucent window, in **both display modes** (`../project_context.md` §4.5): full-screen (nothing floats over it) and windowed (a normal WM-tiled window whose inner tiles ignore outside windows), following what Gate 1 proved.
- Solid fallback when compositor blur is unavailable.

**Rail (region 1)**
- Launcher (1a) toggles the drawer. Workspace indicators (1b) are static (a single workspace) until v0.2. Vertical label (1c) shows the folder name. Clock (1d) is read-only.
- System data (1e) is out of scope.

**Drawer**
- Expand/collapse with the concave fillet and the motion from `design.md` §8. Push vs overlay follows the Stage 2 decision (Q3).
- **Files** section only: tree of the opened folder; open a file into the focused tile. VS Code-style toolbar: **new file, new folder, refresh, collapse all**. Drawer width resizable by dragging its edge.

**Code region (region 4): tiling**
- One layout (dwindle). Split horizontal/vertical, close, focus left/right/up/down, keyboard resize.
- Tile kinds: **editor** (open, edit, save, tree-sitter highlighting, undo) and **terminal** (PTY).
- One tile = one buffer unless Q5 says otherwise.
- Background layer (4b): windowed = none (transparent). Full-screen = `see-through` and `solid` only, drawn across the whole canvas.

**Settings**
- Hard-coded defaults matching the `design.md` §4.1 tokens. No Lua config yet; a read-only `tileide.lua` can come early only if v0.0's config spike is already clean.

## Out of scope
Lua config and hot reload, workspaces 1–9, Config workspace, themes, extensions, LSP/DAP, run/debug, persistence of layout.

## Exit criteria
- [ ] You can do a real 30-minute editing session (open folder → edit several files in 3+ tiles → use a terminal tile) without reaching for another editor.
- [ ] Drawer expand/collapse has no dropped frames on your machine.
- [ ] Cold start and idle RAM are within the Gate 1 budget.
- [ ] Unsaved changes are never lost silently (closing a dirty tile asks).

## Risks
- Editor widget gaps in the chosen toolkit (selection, IME, large files). Mitigation: keep the editor behind a narrow interface so it can be swapped.
- Scope creep into v0.2 (config, workspaces). Rule: if it needs the config engine, it waits.
