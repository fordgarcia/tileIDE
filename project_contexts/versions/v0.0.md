# v0.0 — Spike (go / no-go)

> Part of TileIDE. Feature definitions live in `../project_context.md`; visuals in `../design/design.md`.
> **Status:** planned · **Throwaway code.** Nothing here ships.

## Goal
Destroy or confirm the riskiest assumptions before any real UI is written. This version can end the project cheaply, and that is a success, not a failure.

## What gets built (all disposable)
1. **Transparency + blur:** a transparent window on Hyprland with the compositor's blur visibly working behind it. (T3)
   **Display modes (§4.5):** test full-screen as (a) a layer-shell surface on the top layer and (b) a fullscreen toplevel, and pick the one where nothing floats over it, keyboard focus works and blur stays under the window only. Test windowed mode as a normal Hyprland-tiled window.
2. **Layout skeleton from `../design/annotated_layout.png`:** a full-screen transparent canvas (0), a narrow rail (1), a gap ring on all four sides (2a, 2b), an outlined window (3), and an empty code region (4), with no inner sidebar. (T12)
3. **Sidebar drawer:** the rail expands into a panel with a concave fillet joining it to the rail, and collapses back. Check it animates smoothly and resizes without hacks. (T4, T9)
4. **Tiling:** split the code region into 3+ tiles with gaps, resize with the keyboard, close and refocus, in the chosen base. (T10)
5. **Stack:** build the same three tests (translucent canvas, drawer fillet, tiling) in **R1 (Rust + GTK4)** and **R2 (Rust + GPU-drawn toolkit)**, and run one language server and one debugger over LSP/DAP in each. (T1, T2, T10)
6. **Config (Lua):** embed Lua in the spike, load the sample in `../project_context.md` §6.3, hot-reload one value (e.g. `window_radius`) in a fresh Lua state, and print a file:line error for a deliberate mistake. Try Lua 5.4 and Luau (and LuaJIT if easy); measure startup time and binary size for each. Try to escape the sandbox on purpose (`io.open`, `os.execute`, an infinite loop). (T14)
7. **Background layer (4b):** in **full-screen mode only**, draw an app-side image across the whole canvas (behind rail, gap and translucent tiles) with dim and tile-opacity, next to the see-through mode. Windowed mode stays transparent (`../project_context.md` §4.4). Check it looks right beside the gap, and that text stays readable on a bright photo. (T11)
8. **Measure** cold start and idle RAM for: stock VS Code, Zed (as a Rust reference), the R1 spike and the R2 spike, **on your machine**.

## Gate 1 (all must pass, or the plan changes)
- [ ] Blur + transparency works on Hyprland, and a solid fallback looks acceptable elsewhere.
- [ ] The rail ⇄ drawer fillet renders cleanly and survives window resize.
- [ ] The background layer works in both see-through and app-drawn modes without breaking tiling or legibility.
- [ ] Full-screen mode: no other window floats over the canvas, keyboard focus works, blur applies only under the window. Windowed mode: tiles like a normal window, and the inner tiles are unaffected by new WM windows.
- [ ] Arbitrary tiling in the code region works in the chosen base without fighting its layout engine.
- [ ] At least one language server and one debugger run end to end over LSP/DAP.
- [x] Embedded Lua loads the sample config quickly, reports file:line errors, hot-reloads, and the sandbox blocks file, process and network access and an endless loop. *(spike 2, 2026-10-31: see `spikes/lua-config/RESULTS.md`; endless loops are only fully blocked in Luau)*
- [ ] A toolkit (R1 or R2) is chosen using measured numbers, and a performance budget is written into `../project_context.md` §9.

## Decision this version produces
**Which Rust toolkit** (R1 or R2; fallbacks R3, R4 in `../project_context.md` §5.2) and **which Lua flavour** (5.4, LuaJIT or Luau). The numbers decide, not preference.

## Explicitly out of scope
Real file tree, themes, workspaces, persistence, packaging, any polish.

## Risks
Spike turns into the product ("it mostly works, let's keep it"). Mitigation: delete the spike code after Gate 1 and rebuild v0.1 cleanly.
