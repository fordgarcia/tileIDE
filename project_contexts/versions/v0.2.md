# v0.2 — Config + Workspaces

> **Status:** planned · Depends on: v0.1.

## Goal
Make the app configurable by one short text file, and make workspaces real. This is the version where Veil becomes "Hyprland-like".

## Scope
**Config engine**
- Embedded Lua runtime with a sandboxed `veil.*` API, `require` limited to the config directory, schema validation of the resulting settings, last-good fallback, hot reload (fresh Lua state per reload), time limit on config runs, `veil --check-config`, file:line errors.
- Keybind router (`veil.bind(mods, key, action, arg)`), including tiling actions (split, focus, move, resize, swap).
- Layout options for the code region (e.g. dwindle-like, master-like) as config values. Gap sizes (outer gap, inner gap) are tokens.
- Per-module toggles for the whole sidebar (`sidebar { show_* }`).

**Workspaces (1–9)**
- Switch with `Super+N`; indicators in the rail (1b) update live; vertical label (1c) shows the current project.
- **Each workspace owns:** folder(s), tile layout, open files, terminals, theme override, **optional background override**.
- **The Files tree in the sidebar follows the active workspace.**
- Workspace overview overlay.

**Config workspace**
- A reserved workspace that opens the app's config files in the code region for direct editing, with live preview of changes and inline validation errors. Behaviour (pinned? slot 0? replaces tiles or temporary?) is an open question.
- Sidebar **Config** section lists the files (`veil.lua`, themes, rices).

## Out of scope
Extensions, Themes browsing/installing (only local theme files), run/debug.

## Exit criteria
- [ ] A second person can restyle and rebind the app by editing one text file with no docs beyond the sample.
- [ ] Switching workspaces updates tiles and file tree in < the budget set at Gate 1.
- [ ] A broken config never crashes the app; the last good config stays active and the error is visible.

## Risks
- Config API keeps growing, and Lua makes it easy. Rule: a new function or key needs a real use case from you or a user.
- Lua configs can hang or misbehave. Mitigation: time limit, last-good fallback, trust tiers (`project_context.md` §6.3, T14).
- GUI-made settings (theme picker, background picker) cannot rewrite a Lua file safely. Decide Q15 before building them.
- Workspace persistence (restoring terminals, unsaved buffers) has many edge cases. Define what is **not** restored.

## Open questions
- Is the Config workspace a normal numbered workspace, or a mode that can be toggled over any workspace?
- When you switch workspace, do terminals keep running in the background?
